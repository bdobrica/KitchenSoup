Execution targets

Docker-over-SSH target

Configure a trusted GPU host with Docker and NVIDIA Container Toolkit. Inputs are copied over SSH; the host does not need access to KitchenSoup storage. Target configuration is immutable: create a new target to change hosts or settings.

Enable SSH execution and approve the host key and credential locations in the host application settings first. Enter a credential reference only.

Kubernetes target

Use a prepared GPU namespace with enforced NetworkPolicies and persistent storage for training. Enable Kubernetes execution and approve the kubeconfig reference in application settings first. Add a pinned serving image to enable playgrounds.

Advanced

SageMaker training target

Training on AWS uploads the selected dataset and model bytes to your configured AWS bucket and incurs charges. Provision a regional private ECR trainer image, an unversioned S3 staging bucket, an execution role and a small GPU quota first. Enable SageMaker execution and approve an AWS profile in application settings. Credentials remain on the control plane.

Advanced

One instance per run; retries create a new paid run. Runtime limits do not cap total AWS spending. Stop unwanted jobs and clean up their staging objects after completion.

Runpod training target

Automatically allocates a paid GPU Pod and terminates it after training. Enable Runpod execution, approve API/SSH references and provision SSH host trust first. Operator setup: docs/runpod-training.md.

Advanced

One GPU per Pod. GPU estimates exclude storage and other charges. Idle Pods and pending cleanup can remain billable.
